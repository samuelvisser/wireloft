# Security and Remote Access

WireLoft has two different access-control concepts:

1. **administrator authentication** protects the web UI and protected application API;
2. **RSS feed tokens** authorize private podcast feeds and their media without requiring a podcast client to log into the UI.

Do not confuse them. Enabling an administrator password does not make an existing RSS URL require that password.

## Protect the web UI

Set a long unique administrator password on the container:

```yaml
environment:
  WL_ADMIN_AUTH__PASSWORD: "choose-a-long-unique-password"
```

Restart WireLoft after changing it.

WireLoft consumes the plaintext password at startup, derives its client value, creates an scrypt hash, and removes the plaintext environment value from its own process environment. You can alternatively provide a precomputed `scrypt$...` value through `WL_ADMIN_AUTH__PASSWORD_HASH`.

If neither a password nor valid hash is configured, administrator authentication is disabled.

### Session lifetime

Administrator sessions last 30 days by default (`2592000` seconds). Change `loginSession.ttlSeconds` if you need a different policy. See [[Settings]].

## Protect the Daily Wire session

WireLoft's Daily Wire connection can provide access to member-exclusive content available to your account. Anyone with unrestricted control of your WireLoft instance can potentially use the application's configured capabilities.

That is why administrator authentication is strongly recommended whenever WireLoft is reachable from an untrusted network.

The device authorization flow means WireLoft does not need your Daily Wire password, but its persistent `/config` data still contains authentication/application state that should be protected and backed up securely.

## RSS feed URLs are credentials

A WireLoft RSS URL contains a randomly generated token:

```text
https://wireloft.example.com/feeds/rss/<secret-token>/<show>.xml
```

The token is intentionally sufficient to access the feed without the WireLoft administrator login. Media URLs generated by that feed are under the same tokenized path.

**Anyone with the complete URL can use the feed access you configured.** For a feed that can fall back to premium Daily Wire streams, that means the URL acts like a delegated key to premium media through your WireLoft instance.

Treat it the same way you would treat an API key:

- do not publish it;
- do not include it in screenshots or screen recordings;
- redact it from support logs/issues;
- avoid sending it through insecure chat/email;
- do not commit it to a public repository;
- use HTTPS when it travels over an untrusted network.

### If a feed URL leaks

Open its Stream Profile and click **Regenerate**. WireLoft creates a new token and invalidates the previous token immediately.

After rotation, update your own podcast clients to the new URL.

A client may still retain media it downloaded previously. Token rotation prevents future requests; it cannot erase copies already made by another client.

See [[Podcast-RSS-Feeds]] for the full feed workflow.

## Reverse proxy guidance

When exposing WireLoft through Nginx, Traefik, Caddy, or another reverse proxy:

- terminate HTTPS at the proxy;
- set `WL_ADMIN_AUTH__PASSWORD`;
- forward the normal application/API paths;
- make sure the RSS hostname shown in the Stream Profile is the hostname the podcast client can actually reach;
- forward the tokenized `/feeds/rss/` tree, including enclosure/media requests;
- avoid imposing the WireLoft administrator-login flow on `/feeds/rss/`, because normal podcast applications cannot perform that web login.

You can add your own proxy authentication in front of feeds only if every podcast client you use supports that authentication method. Otherwise the secret RSS token should remain the feed credential.

## LAN, VPN, or public HTTPS

You do not have to expose WireLoft directly to the internet just to use RSS on a phone.

Common patterns are:

- **LAN only** — easiest, but feeds work only while the client can reach the LAN hostname.
- **VPN/overlay network** — keeps WireLoft private while making it reachable remotely.
- **HTTPS reverse proxy** — convenient for normal podcast clients anywhere, but requires careful UI authentication and feed-token handling.

If your podcast application fetches feeds from its own cloud servers rather than directly from the phone, a LAN/VPN-only hostname may not work even while the phone itself is connected. In that case consult the podcast application's feed-fetching model or use an appropriately protected reachable hostname.

## Secret-key persistence

The supplied Docker configuration stores WireLoft's generated secret key at:

```text
/config/wl_secret.key
```

Keep `/config` persistent. Replacing secret/authentication state unexpectedly can invalidate existing application sessions or stored state.

## Configuration secrets

Environment variables have higher priority than `config.yml`. Sensitive values such as administrator passwords, literal crypto keys, and TMDB tokens are generally better supplied through your deployment's secret/environment mechanism than committed in configuration files.

For the complete mapping, see [[Settings]].
